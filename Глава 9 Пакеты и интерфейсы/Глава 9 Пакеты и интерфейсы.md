# Глава 9. Пакеты и интерфейсы

Продолжение: [Интерфейсы. Страницы 256-274](Интерфейсы.%20Страницы%20256-274.md) - реализация интерфейсов, стеки, методы `default`, `static`, `private` и начало главы об исключениях.

> [!info] Границы материала
> Разобраны **печатные страницы 244-255**, то есть страницы **245-256 в PDF**. На странице 244 заканчивается глава 8: обсуждаются методы `Object`, отдельного примера программы там нет. Глава 9 начинается на странице 245. В этом диапазоне основная часть примеров посвящена пакетам, а интерфейсы только вводятся.

## Главное из прочитанного

- **Пакет** объединяет классы, разделяет пространства имён и участвует в управлении доступом. `package` располагают перед импортами и объявлениями типов.
- **Иерархия имён** отражается в каталогах: пакет `a.b.c` соответствует пути `a/b/c`. `javac -d out` создаёт нужные каталоги для `.class` автоматически.
- **Classpath** указывает на корень дерева пакетов. Для `out/mypack/AccountBalance.class` нужен `-cp out`, а запускать следует `mypack.AccountBalance`.
- **Импорт** позволяет писать короткое имя типа. Он не меняет права доступа и не импортирует подпакеты автоматически. Вместо импорта можно указывать полное имя, например `java.util.Date`.
- **Открытый класс** из другого пакета требует `public`; используемые извне конструктор и методы также должны быть доступны. `public` у класса не делает все его поля открытыми.
- **Интерфейс** задаёт контракт для классов. У класса может быть несколько интерфейсов; общая схема объявления начинается на странице 255.
- На странице 244: `equals()` отвечает за сравнение объектов, а `toString()` возвращает их текстовое представление. Это завершение предыдущей темы, поэтому отдельный Java-файл по этой странице не добавлен.

## Таблица доступа

Сводка по таблице 9.1 и примерам на страницах 249-252:

| Где обращаемся к полю | `private` | Без модификатора | `protected` | `public` |
| --- | --- | --- | --- | --- |
| В объявившем его классе | Да | Да | Да | Да |
| В подклассе того же пакета | Нет | Да | Да | Да |
| В другом классе того же пакета | Нет | Да | Да | Да |
| В подклассе другого пакета | Нет | Нет | Да, с ограничением ниже | Да |
| В постороннем классе другого пакета | Нет | Нет | Нет | Да |

Для `protected` из другого пакета доступ разрешён в контексте наследования. Это не означает, что подкласс сможет читать поле у произвольного объекта базового класса. В `Protection2` доступ показан напрямую к унаследованному полю `n_pro`.

## Короткие фрагменты синтаксиса

На странице 246 приведены отдельные объявления пакетов. Это альтернативные строки для разных исходных файлов:

```java
package mypackage;
```

```java
package a.b.c;
```

На странице 253 показаны импорт конкретного класса, импорт типов пакета и эквивалент неявного импорта `java.lang`:

```java
import java.util.Date;
import java.io.*;
import java.lang.*; // Эта строка обычно не нужна: пакет доступен неявно.
```

Эти короткие объявления сохранены в заметке; самостоятельных программ из них не получается. На странице 255 дан шаблон интерфейса с условными типами и именами. Его компилируемый вариант вынесен в `InterfaceTemplate.java` и явно отмечен как адаптация. Конкретный интерфейс `Callback` появляется на следующей печатной странице, 256, за пределами выбранного диапазона.

## Компиляция и запуск

Нужен установленный JDK 17 или новее, команды `javac` и `java` должны быть доступны в терминале. Все команды ниже предназначены для **PowerShell**. Сначала перейдите в папку главы:

```powershell
Set-Location 'E:\GPT\Java\12-Schildt-\Глава 9 Пакеты и интерфейсы'
```

### 1. Простой пакет

```powershell
javac -encoding UTF-8 --release 17 -d .\01-simple-package\out .\01-simple-package\mypack\AccountBalance.java
java -cp .\01-simple-package\out mypack.AccountBalance
```

Ожидаемый вывод:

```text
K. J. Fielding: $123.23
Will Tell: $157.02
--> Tom Jackson: $-12.33
```

### 2. Доступ между пакетами

```powershell
$sources = (Get-ChildItem .\02-access -Recurse -Filter *.java).FullName
javac -encoding UTF-8 --release 17 -d .\02-access\out @sources
java -cp .\02-access\out p1.Demo
java -cp .\02-access\out p2.Demo
```

Конструкторы печатают доступные им значения: `n = 1`, `n_pri = 2`, `n_pro = 3`, `n_pub = 4`. При создании подкласса сначала вызывается конструктор базового класса, поэтому его блок вывода появляется несколько раз. `n_pri` печатается только внутри самого `Protection`.

### 3. Два варианта импорта

```powershell
javac -encoding UTF-8 --release 17 -d .\03-import\with-import\out .\03-import\with-import\MyDate03Import.java
javac -encoding UTF-8 --release 17 -d .\03-import\fully-qualified\out .\03-import\fully-qualified\MyDate03Qualified.java
```

У этих классов нет `main()`: достаточно убедиться, что оба варианта компилируются.

### 4. Открытый Balance

```powershell
javac -encoding UTF-8 --release 17 -d .\04-public-balance\out .\04-public-balance\mypack\Balance.java .\04-public-balance\TestBalance.java
java -cp .\04-public-balance\out TestBalance
```

Ожидаемый вывод:

```text
J. J. Jaspers: $99.88
```

### 5. Общая схема интерфейса

```powershell
javac -encoding UTF-8 --release 17 -d .\05-interface-template\out .\05-interface-template\InterfaceTemplate.java
```

Это объявление контракта, запускать его отдельно нельзя.

## Небольшие упражнения

- В `Derived` раскомментируйте обращение к `n_pri` и посмотрите на ошибку компилятора. Затем верните комментарий.
- Сравните вывод `p1.Demo` и `p2.Demo`: какие поля видны в каждом конструкторе?
- В публичной версии `Balance` временно уберите `public` у класса, затем отдельно у конструктора или `show()`. Каждый раз попробуйте собрать `TestBalance` и восстановите исходный код.
- Объясните, почему classpath указывает на `out`, хотя файл класса лежит в `out/mypack`.
