## Суть материала

### Реализация и полиморфизм: страницы 256-259

`interface` описывает контракт, а `implements` связывает с ним класс. Обычный метод интерфейса без тела неявно является `public abstract`; реализующий его метод класса должен быть `public`. Если часть обязательных методов не реализована, класс должен оставаться `abstract`, как `Incomplete`.

В выражении `Callback06Full c = new Client06Full()` тип переменной определяет, какие методы доступны компилятору, а фактический объект определяет, какая реализация вызывается. Поэтому `c.callback(42)` работает, но `c.nonIfaceMeth()` не компилируется: дополнительный метод есть только в `Client06Full`. После `c = new AnotherClient()` тот же вызов `callback()` выполняет другой код.

### Вложенный интерфейс: страницы 259-260

Интерфейс можно объявить внутри класса: в примере это `A07.NestedIF`. Класс `B07` реализует его, а программа проверяет знак числа. У вложенного в класс интерфейса могут быть разные уровни доступа. В примере он `public`; сам внешний класс `A07` имеет доступ в пределах пакета.

### Один контракт, разные стеки: страницы 260-263

`IntStack08` содержит только операции `push(int)` и `pop()`. `FixedStack08` хранит элементы в массиве постоянной длины; `DynStack08` при заполнении удваивает массив и копирует данные. Переменная типа `IntStack08` может работать с обоими, не зная устройства хранилища. Порядок извлечения - **LIFO**: последним добавили, первым извлекли.

### Константы и наследование: страницы 263-266

Поля интерфейса неявно являются `public static final`. Пример `AskMe` использует общий набор констант в двух классах. На странице 265 автор отдельно отмечает спорность приёма «интерфейс ради констант»; здесь он сохранён для изучения листинга.

Интерфейс расширяет другой интерфейс через `extends`. В примере `B10 extends A10`, поэтому класс `MyClass10 implements B10` должен реализовать все три метода: два из `A10` и один из `B10`.

### Методы default, static и private: страницы 266-273

| Вид метода | Назначение | Как используется в примерах |
| --- | --- | --- |
| Обычный абстрактный | Обязательная операция контракта | Класс реализует `getNumber()`, `push()` и `pop()`. |
| `default` | Готовая реализация для объекта; класс может её переопределить | `MyIFImp` получает `getString()` из интерфейса, `MyIFImp2` возвращает свою строку. |
| `static` | Операция самого интерфейса, без объекта реализации | Вызов `MyIF14.getDefaultNumber()` возвращает `0`. Метод не наследуется реализующим классом или производным интерфейсом. |
| `private` | Внутренний вспомогательный код интерфейса | `getElements()` используется двумя `default`-методами, но недоступен вызывающему коду. |

Методы `default` и `static` появились в JDK 8, закрытые методы интерфейсов - в JDK 9. Наличие реализации методов не добавляет интерфейсу полей состояния отдельного объекта.

Правила выбора стандартной реализации на странице 270:

1. Собственная реализация в классе имеет приоритет над `default`-методом интерфейса.
2. Из двух интерфейсов в цепочке наследования выбирается реализация более конкретного, производного интерфейса.
3. Для двух независимых интерфейсов с конфликтующими реализациями класс должен явно разрешить конфликт своим методом.

Внутри подходящего контекста к реализации прямого родительского интерфейса можно обратиться как `Alpha.super.reset()`. В добавленном запускаемом примере класс явно вызывает обе реализации.

## На что обратить внимание в листингах

- **Версии можно компилировать вместе.** Имена типов различаются суффиксами разделов, поэтому общая сборка главы не вызывает конфликтов. Каждая папка также собирается самостоятельно; команды ниже сохранены для изучения отдельных примеров.
- **`clear()` на странице 269 - заглушка.** Он только печатает сообщение. В демонстрации элемент `10` остаётся в стеке после вызова. Автор предлагает позднее заменить сообщение на `UnsupportedOperationException`.
- **Версия с `private` дана отдельно.** Интерфейс на странице 272 не содержит `clear()` из предыдущего варианта; в файле сохранён именно показанный состав методов.
- **В `AskMe` есть опечатка.** Для `SOON` используется диапазон `75 <= prob < 98`: это 23 значения из 100, то есть 23%, а не 13%, указанных в комментарии книги. Авторский комментарий `// 13%` сохранён; рядом добавлено пояснение к опечатке. Алгоритм сохранён. `MAYBE` объявлен и обрабатывается, но `Question.ask()` его не возвращает.
- **Учебные стеки имеют ограничения.** При извлечении из пустого стека выводится сообщение и возвращается `0`, который также может быть обычным элементом. Для `DynStack08` и `DynStack15` начальный размер должен быть положительным: удвоение нулевой длины не создаёт места. Групповое извлечение не проверяет, хватает ли элементов; `skipAndPopNElements()` действительно удаляет пропущенные элементы.

## Компиляция и запуск в PowerShell

Нужен JDK 17 или новее. `javac` и `java` должны относиться к установленному JDK и быть доступны в терминале. Откройте папку главы:

```powershell
Set-Location 'E:\GPT\Java\12-Schildt-\Глава 9 Пакеты и интерфейсы'
```

Выберите **одну** папку из таблицы ниже и соберите её файлы. Например, для стеков:

```powershell
$example = '08-stack'
$sources = (Get-ChildItem -LiteralPath $example -Filter *.java -File).FullName
$outDir = Join-Path $example 'out'
javac -encoding UTF-8 --release 17 -d $outDir @sources
if ($LASTEXITCODE -ne 0) { throw 'Ошибка компиляции' }
java -cp $outDir IFTest3
```

Для другого примера замените `$example`, повторите сборку и подставьте соответствующий класс в последнюю команду. Сборка создаёт подкаталог `out` внутри выбранного примера.

## Страница 274: начало обработки исключений

Исключение представлено объектом. Ошибка может возникнуть в одном методе, а обрабатываться выше по цепочке вызовов. На странице вводятся пять ключевых слов:

| Слово | Смысл |
| --- | --- |
| `try` | Блок кода, для которого предусмотрена обработка исключений. |
| `catch` | Перехват исключения подходящего типа. |
| `throw` | Явная генерация исключения. |
| `throws` | Объявление исключений, которые метод может передать вызывающему коду; для необработанных проверяемых исключений оно обязательно. |
| `finally` | Блок завершающих действий после `try`/`catch`, в том числе при исключении. |

На этой странице только вводное объяснение. Пример обработки исключения не добавлен, поскольку листинг начинается за пределами выбранного диапазона.
